Core Spring Boot

Fundamental application concepts and bootstrapping.
What is Spring Boot and why is it used?
Spring Boot is a Java-based framework that simplifies building production-ready applications by eliminating complex configuration. It’s widely used because it provides embedded servers, auto-configuration, and streamlined dependency management, making development faster and easier.
Explain the difference between Spring Boot and the Spring Framework.
Spring Framework provides core concepts like dependency injection, AOP, and MVC. Spring Boot sits on top of Spring and adds opinionated auto-configuration, starters, and simplified packaging to help developers start quickly.
How does auto-configuration work in Spring Boot?
Spring Boot’s auto-configuration is the mechanism that automatically sets up beans and configurations based on what’s present on your classpath, your defined beans, and your application properties. It works by scanning available libraries and applying sensible defaults, while still allowing you to override them.Spring Boot scans the classpath and uses `@Conditional` annotations to activate configuration only when certain libraries are present and beans are missing. This makes it possible to get default beans without explicit configuration.
What are Spring Boot starters?
Starters are dependency bundles such as `spring-boot-starter-web` or `spring-boot-starter-data-jpa` that include common related libraries. They simplify dependency management and ensure compatible versions.
How do you bootstrap a Spring Boot project?
Use Spring Initializr, or create a Maven/Gradle project with `spring-boot-starter-parent`, add `spring-boot-starter` dependencies, and create an `@SpringBootApplication` class with a `main()` method calling `SpringApplication.run()`.
How do you exclude specific auto-configurations?
Use `@SpringBootApplication(exclude = {DataSourceAutoConfiguration.class})` or `spring.autoconfigure.exclude` in properties. This is useful when you want to customize or disable a default auto-configuration bean.
What is the role of `SpringApplication` and `ApplicationContext`?
`SpringApplication` starts the application, loads the context, and handles environment setup. `ApplicationContext` is the container that holds beans, manages lifecycle, and processes dependency injection.

Configuration & Properties

Property binding, profiles, external config, and environment order.
How do you externalize configuration?
Externalize configuration through `application.properties`, YAML, environment variables, command-line arguments, or Spring Cloud Config. Spring Boot merges these sources and follows a consistent order when resolving values.In Spring Boot, externalizing configuration means keeping values (like database URLs, API keys, or feature flags) outside of your compiled code so they can be changed without redeploying.
How do Spring profiles work?
Profiles allow you to group beans and configuration for specific environments. Activate profiles with `spring.profiles.active`, and create profile-specific files like `application-dev.yml` or annotate beans with `@Profile("prod")`.
How do you bind properties to a POJO?
A POJO is a Plain Old Java Object — a simple Java class not tied to any framework. It usually contains fields, constructors, and getters/setters, and is widely used to represent data in frameworks like Spring and Hibernate(Better than @Value).Use `@ConfigurationProperties(prefix = "app")` and either `@EnableConfigurationProperties` in a configuration class or register the class as a component. Use `@ConstructorBinding` for immutable binding.
When should you use `.properties` vs `.yml`?
`application.properties` is great for simple flat configuration. `application.yml` is preferable for nested structures, lists, and better readability when configuration grows more complex.
What is `spring.config.import`?
`spring.config.import` lets you load configuration from imported sources such as files, optional locations, or remote config servers. It supports use cases like shared config and environment-specific overrides.spring.config.import is a Spring Boot 2.4+ feature that lets you import additional configuration files or sources into your application.
How is property resolution ordered?
Spring Boot resolves properties in a predefined order: command-line args, environment variables, application properties/YAML, profile-specific files, and defaults. Later sources override earlier ones.Spring Boot resolves properties in a well‑defined order of precedence. This means if the same property is defined in multiple places, the one higher in the order wins.

Dependency Injection & Beans

Bean lifecycle, injection patterns, scope, and advanced wiring.
What are `@Component`, `@Service`, and `@Repository`?
All are stereotypes used to mark classes as Spring-managed beans, but each carries a slightly different semantic meaning. `@Service` indicates service-layer logic, `@Repository` indicates data access and enables exception translation, and `@Component` is a generic stereotype for any bean.
Why prefer constructor injection?
Constructor injection makes dependencies explicit, supports immutability, and is easier to test. It also works cleanly with `final` fields and avoids the pitfalls of field injection.
How do you create a custom bean?
Declare a `@Configuration` class and expose a bean with `@Bean`. Use conditional annotations like `@ConditionalOnMissingBean` when you want Spring to use your custom bean only if no other bean exists.
How do qualifiers and `@Primary` work?

What bean scopes are available?
In Spring, bean scopes define the lifecycle and visibility of a bean within the application context. By default, beans are singleton, but Spring provides several scopes to suit different needs.Common scopes are `singleton` (default), `prototype`, `request`, `session`, and `application`. In web apps, request and session scopes are useful, but they often require proxying with `@Scope(proxyMode = ScopedProxyMode.TARGET_CLASS)`.

Web & REST

REST controllers, validation, error handling, and API best practices.
How do you create REST controllers?
Annotate a class with `@RestController` and map methods using `@GetMapping`, `@PostMapping`, etc. Return objects directly, and Spring will serialize them as JSON by default.
How do you validate request payloads?
Use validation annotations like `@NotNull`, `@Email`, and `@Size` on DTO fields, then annotate the controller parameter with `@Valid`. Handle failures via `@ControllerAdvice` for user-friendly error responses.
How do you handle exceptions globally?
Use `@ControllerAdvice` and `@ExceptionHandler` to centralize exception handling. This ensures consistent HTTP status codes and response bodies for errors across controllers.
What is content negotiation?
Content negotiation selects the response format based on the `Accept` header and configured message converters. JSON is the default, but XML and other formats can be added with additional converters.
How do you implement pagination and sorting?
Use Spring Data's `Pageable` parameter in repository methods and controller endpoints. Return `Page` results and accept query params like `page`, `size`, and `sort`.
What is `@RestControllerAdvice`?
`@RestControllerAdvice` is a specialization of `@ControllerAdvice` that automatically adds `@ResponseBody` to exception handlers, making it ideal for REST APIs because it returns JSON error responses.

Data Access (JPA)

Entity mapping, repository patterns, transactions, and query tuning.
How do you integrate Spring Data JPA?
Add `spring-boot-starter-data-jpa` and a JDBC driver, configure datasource settings, and define interfaces extending `JpaRepository`. Spring Boot auto-configures the `EntityManagerFactory` and data source by default.
How do you write custom JPA queries?
Define repository methods using naming conventions or annotate methods with `@Query` for JPQL/SQL. Use projections and DTO constructors to reduce data transfer when needed.
What are common transaction pitfalls?
Transactions only work on public methods called from outside the bean due to proxies. Checked exceptions don't trigger rollback by default, and long transactions can cause lock contention and poor performance.
How do you test JPA with an in-memory database?
Use `@DataJpaTest` with H2 or another in-memory database. Spring Boot configures the test slice and rolls back transactions after each test to keep the database clean.
What is the N+1 select problem?
The N+1 problem occurs when fetching a collection triggers additional queries for each item. Fix it with `fetch = FetchType.LAZY` and `@EntityGraph` or `join fetch` queries to load needed associations efficiently.
How can you optimize batch inserts?
Enable JDBC batch inserts and tune `hibernate.jdbc.batch_size`. Use `flush()` and `clear()` periodically during large imports to avoid memory pressure.

Testing

Unit, integration, slice tests, and Spring test utilities.
How do you unit test Spring components?
Use JUnit and Mockito for unit tests. For example, mock service dependencies and test behaviour in isolation without loading the full Spring context.
When should you use `@SpringBootTest`?
Use `@SpringBootTest` for full integration tests when you need the entire Spring context. Since it is slower, use it for end-to-end scenarios rather than unit testing.
How do you test controllers in isolation?
Use `@WebMvcTest` and `MockMvc` to test the controller layer without loading the full application. Mock service dependencies with `@MockBean`.
How do you test repositories in isolation?
Use `@DataJpaTest` to load only JPA-related components and a lightweight database. This ensures repository behavior is verified without unrelated beans.
What are test slices?
Test slices like `@WebMvcTest`, `@DataJpaTest`, or `@JsonTest` load only a portion of the application context to make tests faster and more focused.

Security & Auth

Authentication, authorization, JWT, and advanced access controls.
How do you secure a Spring Boot application?
Add `spring-boot-starter-security`. Define a `SecurityFilterChain` bean or extend a security configuration class, set up authentication providers, and protect URLs with authorization rules.
How does JWT authentication work?
Authenticate users once, issue a signed JWT, and validate it for each subsequent request. The JWT contains claims and may be verified using a secret or public key.
What is method-level security?
Use `@EnableMethodSecurity` and annotations like `@PreAuthorize`, `@PostAuthorize`, or `@Secured` to protect service methods based on roles or expressions.
How do you secure actuator endpoints?
Use `management.endpoints.web.exposure.include` to limit endpoints, configure endpoint security in `application.properties`, and apply HTTP basic or OAuth protection to sensitive endpoints.
What is OAuth2 resource server support?
Spring Security can act as an OAuth2 resource server, validating JWT tokens issued by an authorization server and applying scopes or roles to secure endpoints.

Actuator, Monitoring & Observability

Health, metrics, tracing, and production visibility.
What is Spring Boot Actuator?
Actuator exposes built-in endpoints for health, metrics, environment, and application information. It is a production-ready feature set for monitoring and management.
How do you add metrics and tracing?
Add Micrometer to collect metrics, and configure a backend like Prometheus/Grafana. For tracing, use Spring Cloud Sleuth or OpenTelemetry to capture request traces and export them to Jaeger or Zipkin.
How do you create custom Actuator endpoints?
Implement a custom endpoint using `@Endpoint` and expose operations with `@ReadOperation`, `@WriteOperation`, or `@DeleteOperation`. Register it in the application context.
How do you secure Actuator endpoints?
Restrict exposure using `management.endpoints.web.exposure.include` and enable endpoint security using Spring Security. Expose only required endpoints in production.
What are health groups?
Health groups let you aggregate specific health indicators into named groups, so you can expose a subset of services like readiness and liveness separately.

Microservices & Spring Cloud

Distributed architecture, service discovery, config, and resilience.
How does Spring Boot fit into microservices?
Spring Boot makes services self-contained and easy to package. Spring Cloud then adds distributed features like config servers, discovery, load balancing, and distributed tracing.
What is Spring Cloud Config?
Spring Cloud Config provides centralized external configuration, often backed by Git. It allows services to pull config dynamically and manage environment-specific values consistently.
How does service discovery work?
Service discovery registers instances with a registry like Eureka or Consul. Clients then resolve service names instead of hard-coded addresses, enabling dynamic scaling and resilient routing.
What is client-side load balancing?
Client-side load balancing sends requests to different service instances from the client, typically using a library like Spring Cloud LoadBalancer. It enables retry and weighted routing without a separate load balancer.
How does distributed tracing help?
Distributed tracing tracks requests through multiple services, helping you identify latency hotspots and failures. It typically uses headers propagated through service calls and visualizes spans in tools like Jaeger.

Messaging & Integration

Event-driven design, messaging reliability, and integration patterns.
How do you integrate Kafka or RabbitMQ?
Use Spring for Apache Kafka or Spring AMQP. Define listeners with `@KafkaListener` or `@RabbitListener`, configure templates for sending messages, and manage topics or queues in application properties.
How do you build reliable message processing?
Implement acknowledgements, retries with backoff, dead-letter queues, and idempotent consumers. Consider transaction support where the broker and application both need consistency.
What is the difference between pub/sub and point-to-point?
Pub/sub broadcasts messages to multiple subscribers, while point-to-point delivers each message to a single consumer. Choose based on whether multiple services should react to the same event or only one should process it.
How do you ensure exactly-once semantics?
Exactly-once processing is difficult. Use idempotent consumers, deduplication, transactional producers/consumers, and broker features when available. Kafka transactions can help but require careful design.

Reactive & WebFlux

Reactive programming, non-blocking APIs, and advanced WebFlux patterns.
When should you use WebFlux?
Use WebFlux for highly concurrent, I/O-bound workloads where non-blocking behavior can improve scalability. It requires reactive libraries and is best suited for streaming or high-traffic endpoints.
What are the differences between MVC and WebFlux?
MVC is blocking and uses one thread per request. WebFlux is non-blocking and uses reactive streams (`Mono` and `Flux`) to handle asynchronous data flows with fewer threads.
How do you use `WebClient`?
`WebClient` is Spring's reactive HTTP client. Create a `WebClient`, invoke methods like `get()` or `post()`, and work with `Mono`/`Flux` responses for non-blocking integration with other services.
What is backpressure?
Backpressure allows a reactive consumer to control the rate at which a producer emits data. It prevents fast producers from overwhelming slower consumers and is fundamental to stable reactive streams.

Performance, Troubleshooting & Advanced

Profiling, tuning, observability, and production hardening.
How do you profile and troubleshoot slowness?
Use JVM profilers, thread dumps, GC logs, and APM tools. Analyze slow database queries, thread contention, and high memory usage with Actuator metrics and built-in JVM diagnostics.
How do you tune datasource connection pools?
Set pool size, connection timeout, and validation queries. HikariCP is the default pool in Spring Boot and usually performs well when configured according to your database load.
How do you optimize startup time?
Reduce classpath scanning, avoid unnecessary auto-configurations, and use `spring.main.lazy-initialization=true` or Spring Boot native image support. Keep dependencies minimal and avoid heavy startup tasks.
What are advanced hardening practices?
Use readiness and liveness probes, secure configuration stores, limit endpoint exposure, implement authentication/authorization, and use circuit breakers to protect downstream services.

Deployment & DevOps

Packaging, Docker, CI/CD, and production deployment patterns.
How do you build and run an executable JAR?
Use `mvn package` or the Gradle bootJar task. The resulting fat JAR contains dependencies and can be run with `java -jar app.jar`.
How do you Dockerize a Spring Boot application?
Create a Dockerfile using a JRE base image, copy the built JAR, and run it with `java -jar`. Use multi-stage builds for smaller images and add healthchecks or non-root users.
What CI/CD practices are common for Spring Boot?
Automate builds, tests, and packaging. Use pipelines to promote artifacts through environments, perform smoke tests, and deploy immutable artifacts with blue/green or canary releases.
What is a layered JAR?
A layered JAR separates dependencies, resources, and application classes into layers. It speeds up container image builds and deployment by reusing unchanged layers.

Logging & Troubleshooting

Logging setup, centralized error tracking, and operational diagnostics.
How do you configure logging in Spring Boot?
Spring Boot uses Logback by default and supports configuration through `application.properties` or `logback-spring.xml`. Adjust `logging.level.*`, appenders, and patterns as needed.
How do you add MDC/correlation IDs to logs?
Use MDC (Mapped Diagnostic Context) in filters to add a correlation ID to logs. Include the MDC value in the log pattern so every request can be traced through logs.
How do you centralize logs?
Forward logs to a centralized system like ELK, EFK, or Splunk. Use structured logging in JSON format to make log searching and analysis easier.
How do you handle error reporting?
Capture exceptions with global error handlers and send important errors to monitoring systems. Use application insights or Sentry to track issues and correlated log events.

Common Interview Extras

High-value topics, advanced patterns, and frequently asked tough questions.
What is a correlation ID and how do you implement it?
A correlation ID associates logs and requests across services. Generate it at the gateway or first entry point, propagate it in headers, and add it to log MDC for traceability.
Explain circuit breakers and resilience patterns.
Circuit breakers stop calls to failing services after a threshold is reached. Use retry, fallback, bulkhead, and timeouts with libraries like Resilience4j to build resilient applications.
How do you version REST APIs?
Version APIs using URL paths, headers, or content negotiation. Maintain backward compatibility, document changes clearly, and deprecate older versions gradually.
What is eventual consistency?
Eventual consistency means data updates propagate asynchronously and may not be immediately visible everywhere. Use event-driven workflows and compensating actions to keep distributed data eventually consistent.
How do you implement graceful shutdown?
Enable Spring Boot graceful shutdown with `server.shutdown=graceful` and configure timeouts. This allows in-flight requests to finish before the application stops.
